## 0. 한 단계를 진행하는 방법

1. **받기** — 아래 [§2](#2-받기--매번-시작할-때) 명령을 실행한다.
2. **지금 단계 찾기** — [§1 진행표](#1-진행표)에서 체크 안 된 **첫** 단계의 파일을 연다.
3. **사람이 먼저 할 일**이 있으면 먼저 한다 (계정·대시보드·사진 등).
4. **AI에게 맡기기** — AI 코딩 도구(Claude Code 등)를 ESG 폴더에서 열고, 아래 문장에서 파일 이름만 바꿔 넣는다.
   ```text
   AGENTS.md와 개발/단계/S03_로그인홈.md를 읽고, 그 파일의 "AI 지시"대로 진행해줘. 끝나면 확인 방법을 알려주고 멈춰.
   ```
5. **확인** — 단계 파일의 "확인" 항목을 **전부** 직접 해 본다. 하나라도 안 되면 올리지 않는다.
6. **체크** — 이 파일 §1에서 그 단계를 `[x]`로 바꾸고 `완료:` 뒤에 시각을 적는다.
7. **올리기** — 단계 파일의 "올리기" 명령을 **한 줄씩** 실행한다 ([§3](#3-올리기--단계를-마칠-때) 규칙).
8. **막히면** — 단계 파일의 "막히면"을 보고, 그래도 안 되면 **현장 멘토님께 단계 파일과 오류 화면을 함께 보여 드린다.**

## 2. 받기 — 매번 시작할 때

**처음 한 번만** (명령 프롬프트에서 한 줄씩):
```
cd %USERPROFILE%
git clone https://github.com/Urindo-do/ESG.git
cd ESG
```

**그다음부터 매번**:
```
cd %USERPROFILE%\ESG
git status
git pull --rebase
```
- `git status`가 `nothing to commit, working tree clean`이 아니면 **멈춘다** — 지난 작업이 덜 올라간 것이다. 지난 단계의 "올리기"부터 마무리한다.
- PowerShell 창이라면 첫 줄만 `cd ~\ESG`로 바꾼다.

## 3. 올리기 — 단계를 마칠 때

- **단계 파일의 "올리기" 명령을 그대로, 한 줄씩** 실행한다. 명령 뒤에 `#` 설명을 붙이지 않는다 (명령 프롬프트는 설명까지 명령으로 읽는다).
- `git add .` 이나 `*` 는 쓰지 않는다 (엉뚱한 파일이 올라가고, 명령 프롬프트는 `*`를 풀어 주지 않는다).
- `git status`에 **`.env.local`** 이 보이면 **멈춘다** (키가 올라갈 수 있음). `node_modules`가 보여도 멈춘다.
- `git pull --rebase`에서 `CONFLICT`가 나오면 `git rebase --abort`를 실행하고 멘토님께 도움을 요청한다.
- 올린 뒤 GitHub 저장소 화면에서 방금 올린 커밋이 보이는지 확인한다.

## 6. 시간이 모자랄 때 자르는 순서

기능 동결 시각까지 못 끝낸 단계는 **아래 순서로** 뺀다. 순서를 미리 합의해 두면 급할 때 다투지 않는다.

1. **S13 인증 기록** — 뺀다. 발표에서 "기록 화면은 향후"로 설명
2. **S12 3D 마을** — `village.js`의 `MODE`를 `'2d'`로 두고 2D 대역으로 시연
3. **S8의 환경표지 데이터 추가** — 환경성적표지만으로 진행 (시연 제품은 환경성적표지 파일에 있음)
4. **S11의 시연용 시간 경과** — 감소 계산은 자동 테스트(S5)로 보여 주고 버튼은 생략

**빼면 안 되는 것**: S1~S7, S9(제품), S10(문구), S14~S15
- S9의 후보 선택 화면은 **시연 제품이 자동 확정되는 것을 확인한 뒤에만** 생략할 수 있다 (`아이시스`만으로는 7개 변형이 검색됨).
