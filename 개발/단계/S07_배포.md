# S7. 배포 — 휴대폰으로 접속

| 예상 | 난이도 | 앞 단계 |
|---|---|---|
| 30분 | ★☆☆ | S6 |

**끝나면**: `https://…vercel.app` 주소가 생기고, 휴대폰으로 접속해 가입부터 빈 그릇 인증까지 된다. 이후에는 main에 올릴 때마다 자동으로 다시 배포된다.

## 사람이 할 일 (AI 없이)

1. [vercel.com](https://vercel.com)에 **GitHub 계정으로 로그인**
2. **Add New → Project** → `Urindo-do/ESG` 저장소 **Import**
3. 설정
   - **Root Directory**: `frontend`
   - Framework Preset: Vite (자동으로 잡힘)
   - Build Command: `npm run build` / Output Directory: `dist`
   - **Environment Variables**: `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY` — `.env.local`과 같은 값 (**공개 키만**)
4. **Deploy** → 완료되면 주소를 복사한다
5. **Google 로그인에 배포 주소 등록** (S3에서 켠 Google 로그인이 배포 주소에서도 되게)
   - Supabase → Authentication → URL Configuration → **Site URL**을 배포 주소로 바꾸고, Redirect URLs에 `https://배포주소/**` 추가 (개발용 `127.0.0.1` 주소들은 그대로 둔다)
   - Google Cloud Console → Google Auth Platform → Clients → S3에서 만든 웹 클라이언트 → 승인된 JavaScript 원본에 `https://배포주소` 추가 → 저장 (반영까지 몇 분 걸릴 수 있음)

## AI 지시

```text
[작업] README.md의 "참고 문서" 목록 맨 위에 배포 주소를 한 줄 추가한다. (S7)
[배포 주소] (여기에 붙여넣기)
[규칙] README.md의 그 한 줄 말고는 고치지 않는다. git 명령 실행 금지.
```

## 확인

- [ ] 휴대폰으로 배포 주소 접속 → 「Google로 시작하기」 → 「빈 그릇 인증」 → 카메라가 열림 → 촬영 → +10
  - 주소는 크롬·사파리로 연다. 카카오톡 안에서 열면 Google이 로그인을 막는다
- [ ] 노트북 브라우저에서도 같은 주소로 로그인·인증이 된다
- [ ] 연습 페이지(`village-dev.html`)는 배포 주소에 없어도 정상 (개발용이라 빌드에 넣지 않음)

## 올리기

```
git status
git add README.md 개발/체크리스트.md
git commit -m "docs: S7 배포 주소 추가"
git pull --rebase
git push
```
올린 뒤 Vercel 화면에서 새 배포가 자동으로 시작되는지 확인한다.

## 막히면

- Google 로그인 후 `127.0.0.1`로 돌아간다 → 5번의 Site URL·Redirect URLs
- 배포는 됐는데 화면이 하얗다 → Vercel의 Environment Variables 이름·값 확인 후 **Redeploy**
- 빌드 실패 → Vercel Build Logs의 빨간 줄을 AI에게 붙여넣기 (Root Directory가 `frontend`인지 먼저 확인)
