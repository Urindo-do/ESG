# S3. 로그인·홈

| 예상 | 난이도 | 앞 단계 |
|---|---|---|
| 60분 (+ Google 설정 20분) | ★★☆ | S2 |

**끝나면**: 「Google로 시작하기」로 로그인하면 홈에 닉네임과 점수 50·'보통'이 보인다. 테스트용 이메일 로그인도 남아 있다. 브라우저에서 점수를 몰래 바꾸려 해도 바뀌지 않는다.

> **9/18 변경 — 로그인은 Google이 기본, 이메일은 테스트용.** 사용자는 비밀번호 없이 한 번에 들어오고, Supabase 기본 메일 제한(팀원 주소만)에도 걸리지 않는다. 이메일 로그인은 두 번째 계정으로 권한을 확인할 때 쓰려고 남긴다. 이유는 [명세 §6](../연결명세.md#6-결정-기록).

## 사람이 먼저 할 일

1. 받기 ([체크리스트 §2](../체크리스트.md#2-받기--매번-시작할-때))
2. `frontend/.env.local` 파일 만들기 — `frontend/.env.example`을 복사해 이름을 바꾸고 두 값을 넣는다
   ```
   VITE_SUPABASE_URL=https://프로젝트주소.supabase.co
   VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_로시작하는값
   ```
   - 값 위치: Supabase 대시보드 → Project Settings → API Keys (URL은 `/rest/v1/` 없이 `.supabase.co`까지)
   - ⚠️ **공개 키만.** `sb_secret_…`·`service_role`은 넣지도, AI에게 보여주지도 않는다
   - 이 파일은 `.gitignore`에 걸려서 올라가지 않는다
3. **Google 로그인 켜기** (약 20분, 한 번만)
   1. Supabase 대시보드 → **Authentication → Sign In / Providers → Google** 을 열어 **Callback URL**(`https://프로젝트주소.supabase.co/auth/v1/callback`)을 복사해 둔다
   2. [Google Cloud Console](https://console.cloud.google.com) → 새 프로젝트(예: `hwangyeongi`) → **Google Auth Platform** → 시작하기
      - 앱 이름 `환경이`, 지원 이메일 = 내 Gmail
      - 대상(Audience): **외부(External)**
      - 범위(Data Access)는 **추가하지 않는다** — 기본 `openid`·`email`·`profile`만 쓰면 테스트 사용자 등록·7일 만료·경고 화면이 없다 ([Google 도움말](https://support.google.com/cloud/answer/15549945))
   3. **Clients → 클라이언트 만들기 → 웹 애플리케이션**
      - 승인된 JavaScript 원본: `http://127.0.0.1:5173`, `http://127.0.0.1:5174`, `http://localhost:5173` (S7에서 배포 주소 추가)
      - 승인된 리디렉션 URI: 1에서 복사한 **Supabase Callback URL**
      - 만들기 → **클라이언트 ID**와 **클라이언트 보안 비밀번호**가 나온다
   4. Supabase → Authentication → Sign In / Providers → **Google** → 켜기 → 클라이언트 ID·보안 비밀번호 붙여넣기 → 저장
      - ⚠️ **클라이언트 보안 비밀번호는 Supabase 대시보드에만.** 저장소·`.env.local`·단톡·AI 대화에 쓰지 않는다
   5. Supabase → Authentication → **URL Configuration**
      - Site URL: `http://127.0.0.1:5173`
      - Redirect URLs에 추가: `http://127.0.0.1:5173/**`, `http://127.0.0.1:5174/**`, `http://localhost:5173/**`
4. 이메일 로그인(테스트용)을 쓰려면 **S2의 Confirm email 끄기**가 되어 있어야 한다 — Authentication → Sign In / Providers → Email에서 확인
   - 켜져 있으면 가입할 때 확인 메일을 보내려다 막힌다 (기본 메일은 팀원 주소에만 감)

## AI 지시

```text
[작업] 로그인(Google 기본 + 테스트용 이메일)과 홈 화면을 Supabase에 연결한다. (S3)

[먼저 읽기] AGENTS.md, 개발/연결명세.md 의 §0-1, §2-1, §2-5, §2-6, §4, 기획서/환경이_기획서_복붙용.md 의 "주요 화면" ①②

[만들거나 고칠 파일] frontend/src/main.js, frontend/src/app/supabase.js, frontend/src/app/screens/login.js, frontend/src/app/screens/home.js, frontend/.env.example (필요하면 frontend/src/app/ 안의 스타일 파일, @supabase/supabase-js 의존성 추가를 위한 frontend/package.json·package-lock.json)
1. supabase.js — frontend/.env.local의 두 환경변수로 클라이언트를 만든다. 개발 모드(import.meta.env.DEV)일 때만 window.__supabase 에 넣는다 (확인용).
2. login.js
   - 맨 위 주 버튼 「Google로 시작하기」: supabase.auth.signInWithOAuth({ provider: 'google', options: { redirectTo: window.location.origin } }). 추가 scope는 요청하지 않는다.
   - 그 아래 접을 수 있는 영역 "이메일로 로그인 (테스트용)": 이메일·비밀번호 로그인과 회원가입(이메일·비밀번호·닉네임). 닉네임은 가입할 때 사용자 메타데이터 nickname 으로 넘긴다.
   - Google에서 돌아온 주소에 error / error_description 이 있으면 쉬운 한글 안내를 보여주고 주소창에서 그 부분을 지운다.
   - 오류는 쉬운 한글 문장으로 보여준다. 가능하면 error.code 로 구분한다 (예: email_address_invalid → 쓸 수 없는 이메일 주소, email_address_not_authorized → 지금은 이 이메일로 가입할 수 없음). 모르는 오류는 console.error 로 원본 오류를 남기고, 화면에는 쉬운 문장과 오류 코드만 짧게 보여준다.
3. home.js — 마을(createVillage)을 띄우고 profiles에서 내 nickname·score를 읽어 점수를 반영한다. 닉네임을 화면에 작게 보여준다 (마을 모듈 파일은 고치지 않고 src/app/ 쪽에서). 남은 횟수는 { meal: 3, product: 2, phrase: 10 } (// 임시: S11에서 get-status로 교체). 로그아웃 버튼. 미션 버튼을 누르면 "곧 열려요" 안내만 (// 임시: S4에서 촬영 화면 연결). Google 계정의 이름·프로필 사진은 쓰지도 보여주지도 않는다.
4. main.js — 로그인 상태면 홈, 아니면 로그인 화면. 새로고침해도, Google에서 돌아와도 로그인이 유지된다. 첫 실행 때 반드시 한 화면이 그려진다.

[규칙] 점수나 기록을 브라우저에서 DB에 쓰지 않는다. 비밀 키·Google 클라이언트 보안 비밀번호를 쓰지 않는다 (프론트에 필요 없음). 촬영·판정은 아직 만들지 않는다. git 명령 실행 금지.

[끝나면] 파일 목록과 확인 순서를 알려주고 멈춘다.
```

## 확인

`frontend` 폴더에서 `npm run dev` (`.env.local`을 만들거나 고쳤으면 서버를 껐다 켠다). 터미널에 나온 주소(5173 또는 5174)로 연다.

- [ ] 「Google로 시작하기」 → Google 계정 선택 → 앱으로 돌아와 홈이 나오고, 닉네임 '새싹'·점수 50·'보통'이 보인다
- [ ] 새로고침해도 로그인이 유지되고, 로그아웃하면 로그인 화면이 나온다
- [ ] 대시보드 Table Editor의 `profiles`에 그 계정의 새 행이 있다 (닉네임 '새싹', Google 이름이 아님)
- [ ] 테스트용 이메일로 가입 → 홈으로 가고 입력한 닉네임이 보인다 (주소는 실제로 있는 도메인으로. 예: 본인Gmail+test1@gmail.com — 확인 메일은 가지 않는다)
- [ ] **점수 조작이 막힌다** — 로그인한 상태에서 `F12` → Console에 아래 한 줄을 붙여넣고 Enter
  ```
  const { data: { user } } = await __supabase.auth.getUser(); await __supabase.from('profiles').update({ score: 100 }).eq('id', user.id).select();
  ```
  → 결과의 `data`가 **빈 배열 `[]`** 이고, 새로고침해도 점수가 **50 그대로**다
  (크롬이 붙여넣기를 막으면 Console에 `allow pasting`을 입력하고 다시 붙여넣는다)
- [ ] **남의 정보가 안 보인다** — Google 계정과 테스트 이메일 계정이 둘 다 있는 상태에서, Console에 `await __supabase.from('profiles').select()` → **내 행 1개만** 나온다
- [ ] 휴대폰 — 노트북과 같은 와이파이에서 `npm run dev -- --host` → 터미널의 Network 주소로 접속하면 로그인 화면이 보인다
  - 휴대폰에서 Google 로그인까지 해 보려면 그 Network 주소(예: `http://192.168.0.12:5173/**`)를 5번 Redirect URLs에 추가한다. 안 하면 이메일 로그인으로 확인해도 된다
  - **카카오톡·인스타그램 안에서 링크를 열면 Google이 로그인을 막는다**(`disallowed_useragent`). 크롬·사파리로 연다

## 막히면

- 화면이 배경색만 나오고 비어 있다 → `main.js`의 첫 화면 그리기 확인 (9/18에 한 번 고침: 첫 로그인 이벤트를 건너뛰던 문제)
- 「문제가 생겼어요」 → F12 Console의 빨간 오류나 Network 탭의 `signup`·`token` 요청 응답에서 `error_code`를 본다
  - `email_address_not_authorized` → Confirm email이 켜져 있음 (위 4번)
  - `email_address_invalid` → `test.com` 같은 가짜 도메인 대신 실제 도메인 주소로
- Google 화면에서 `redirect_uri_mismatch` → Google 클라이언트의 리디렉션 URI가 Supabase Callback URL과 **글자 하나까지** 같은지
- Google 로그인 후 엉뚱한 주소(예: `localhost:3000`)로 간다 → Supabase URL Configuration의 Site URL·Redirect URLs (3-5번)
- `Unsupported provider: provider is not enabled` → Supabase에서 Google 켜기·저장 (3-4번)
- `Invalid API key` → `.env.local` 값 확인 후 서버 재시작
- `Database error saving new user` → S2 트리거 확인
- 점수 조작이 **성공**해 버린다 → 멈추고 S2의 RLS 정책을 다시 본다 (update 정책이 있으면 안 됨)
