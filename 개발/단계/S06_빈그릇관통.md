| 예상 | 난이도 | 앞 단계 |
|---|---|---|

**끝나면**: 휴대폰(또는 노트북)에서 로그인 → 빈 그릇 촬영 → **진짜 AI 판정** → +10 → 홈의 점수가 60 · '깨끗'으로 바뀐다. 로그인·사진 저장·서버 함수·AI·DB가 **한 줄로 이어진 것**을 확인하는 가장 중요한 단계다.

## 사람이 먼저 할 일

1. 받기 ([체크리스트 §2](../체크리스트.md#2-받기--매번-시작할-때))
2. **테스트 사진 찍기** — [시연/README.md](../../시연/README.md) 규칙대로 `시연/사진/`에 저장
   - 빈 그릇 4장(같은 그릇이라도 각도를 바꿔서) · 음식이 남은 그릇 2장 · 국물이나 소스만 조금 남은 그릇 1장
3. **함수 비밀값 넣기** — Supabase 대시보드 **Edge Functions**의 Secrets 화면에서 추가
   - `LLM_API_KEY` = LLM API 키
   - `LLM_MODEL` = S0에서 정한 모델 이름
4. **Supabase CLI 연결** — 명령 프롬프트, 저장소 폴더에서 한 줄씩
   ```
   npx supabase login
   npx supabase link --project-ref 프로젝트ID
   ```
   - `프로젝트ID` 자리에는 대시보드 **Project Settings → General**의 Project ID를 넣는다
   - DB 비밀번호를 물으면 S0에서 보관한 비밀번호 (모르면 Enter로 넘어가도 된다고 나오면 넘어간다)

## AI가 끝난 뒤 사람이 할 일 — 배포

```
npx supabase functions deploy verify-mission --use-api
```
- `--use-api`는 **Docker 없이** 배포하는 옵션이다 ([공식 안내](https://supabase.com/changelog/33613-deploy-edge-functions-from-cli-without-needing-docker-import-files-outside-of-su))
- 함수를 내 컴퓨터에서 띄우는 `supabase functions serve`는 Docker가 필요하니 쓰지 않는다. 고칠 때마다 다시 배포해서 확인한다.

## 막히면

- 함수 오류는 먼저 **대시보드 Edge Functions → verify-mission → Logs**를 본다. 빨간 줄을 AI에게 그대로 붙여넣는다
- 401 → 로그인한 상태인지, 화면이 `supabase.functions.invoke`로 부르는지
- 502 `llm_failed` → 비밀값 이름(`LLM_API_KEY`, `LLM_MODEL`), 모델 이름 철자, 제공사 결제·한도
- 판정이 계속 `retake` → AI 응답이 명세 JSON 모양인지 Logs로 확인
- 여기서 막히면 **다음 단계로 넘어가지 않는다.** 멘토님께 이 파일과 Logs 화면을 보여 드린다
