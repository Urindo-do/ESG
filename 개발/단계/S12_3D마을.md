# S12. 3D 환경이 마을

| 예상 | 난이도 | 앞 단계 |
|---|---|---|
| 120분 | ★★★ | S11 |

**끝나면**: 2D 대역 자리에 Three.js 3D 마을과 캐릭터가 들어가고, 점수에 따라 5단계로 모습이 바뀐다. 마을 API는 그대로라 다른 화면은 고치지 않는다.

**시간 약속**: 시작할 때 **끝낼 시각**을 정한다 ([체크리스트 §5](../체크리스트.md#5-시간)의 기능 동결 전). 그때까지 안 되면 `MODE = '2d'`로 두고 올린다 — 2D로도 시연은 된다.

## AI 지시

```text
[작업] 2D 대역 마을을 Three.js 3D 마을로 바꾼다. 마을 API(명세 §4)는 그대로 유지한다. (S12)

[먼저 읽기]
- AGENTS.md, 개발/연결명세.md 의 §1(청결 5단계), §4(마을 API)
- 기획서/환경이_3D화면_프롬프트.md — 이 단계의 핵심 명세 (코드 블록 전체)
- 기획서/환경이_캐릭터_콘셉트.png — 캐릭터 모습 기준
- reference/danbi-hanok-day/ — 모듈 나누는 방식과 성능 설정 참고 (수정 금지)

[캐릭터 이름] (S0에서 정한 이름을 적기) — 이름표·표지판에 이 이름을 쓴다. 콘셉트 이미지 속 글자와 달라도 이 이름을 따른다.

[만들거나 고칠 파일] frontend/src/village/ 아래와 frontend/village-dev.html만. village2d.js는 지우지 않는다.
1. 3D 프롬프트의 코드 구조(scene/, character/, props/, behaviors/, ui/)를 frontend/src/village/ 아래에 만든다. 프롬프트의 main.js(개발용 실행) 역할은 dev.js가 맡는다.
2. village3d.js — 명세 §4의 API 6개를 3D로 구현. 청결 경계값은 states/cleanliness.js에서만 가져온다.
3. village.js — MODE를 '3d'로. 3D를 시작할 수 없으면(WebGL 불가 등) 자동으로 2D 대역을 쓴다.
4. dev.js — 연습용 페이지의 점수 슬라이더·남은 횟수·celebrate 버튼이 3D에서도 동작하게.

[규칙] 로그인·카메라·Supabase를 다루지 않는다. 패키지를 새로 설치하지 않는다 (three는 이미 있음). 휴대폰 성능을 위해 로우폴리, 그림자 수 제한, 픽셀 비율 상한 2. git 명령 실행 금지.

[순서] 한 번에 다 만들지 말고 아래 순서로, 각 순서가 끝날 때마다 멈추고 사람이 연습용 페이지에서 확인한 뒤 계속한다.
① 장면(마을)과 캐릭터 → ② 청결 5단계 연출과 정화 효과 → ③ 자동 행동과 물건 클릭 행동 → ④ 화면 위 UI(게이지·남은 횟수·미션 버튼)와 API 연결

[끝나면] 확인 순서를 알려주고 멈춘다.
```

## 확인

`npm run dev` 후 연습 페이지(`village-dev.html`)와 앱 홈(`/`)에서

- [ ] 캐릭터와 마을이 콘셉트 이미지와 비슷한 분위기이고, 이름표·표지판이 정한 이름이다
- [ ] 슬라이더 19↔20, 39↔40, 59↔60, 79↔80에서 단계가 1~2초에 걸쳐 부드럽게 바뀐다. 점수가 오를 때 정화 효과가 보인다
- [ ] 단계마다 1분씩 지켜보면 자동 행동이 달라진다 (꼬질꼬질 이하에서는 시무룩하게 앉기·먼지 털기)
- [ ] 미션 버튼·점수 게이지·남은 횟수가 3D 화면 위에 보이고, 버튼을 누르면 촬영 화면으로 간다 (앱 홈)
- [ ] 로그인한 앱 홈에서 실제 점수대로 보이고, 인증 후 돌아오면 +점수와 함께 모습이 바뀐다
- [ ] 휴대폰(배포 주소)에서 세로 화면이 끊기지 않는다
- [ ] **정한 시각까지 안 되면**: AI에게 "village.js의 MODE를 '2d'로 바꿔줘" → 2D로 확인 → 올린다
