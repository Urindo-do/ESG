# S4. 촬영·결과 화면 (가짜 판정)

| 예상 | 난이도 | 앞 단계 |
|---|---|---|
| 60분 | ★★☆ | S3 |

**끝나면**: 미션 버튼 → 촬영 → 사진이 Supabase에 **진짜로** 올라가고 → **가짜** 판정 결과 6가지가 각각 알맞은 화면으로 나온다. 진짜 AI 판정은 S6부터 붙는다.

**왜 가짜부터?** 서버가 없어도 화면을 끝까지 만들어 볼 수 있고, 로딩·실패 같은 화면도 미리 준비된다. 나중에 한 줄(전환표)만 바꾸면 진짜 서버로 간다.

> **9/18 참고 — 게스트 모드는 이 단계에서 건드리지 않는다.** S3에서 "로그인 없이 둘러보기"(게스트)가 추가됐다. 게스트는 로그인 계정이 없어서 실제 사진 업로드(Storage RLS)가 안 되고, 지금은 `home.js` 안에서 버튼을 누르면 바로 점수가 바뀌는 자체 로컬 로직(`GUEST_POINTS`)으로 동작한다. 이 단계의 "진짜 촬영→업로드→가짜 판정" 흐름은 **로그인 상태(`session` 있음)에만** 연결하고, 게스트 쪽 버튼은 지금 그대로 둔다.

## 사람이 먼저 할 일

- 받기 ([체크리스트 §2](../체크리스트.md#2-받기--매번-시작할-때))
- 테스트용 사진 2~3장을 노트북에 준비 (아무 사진이나 됨, 얼굴 없는 것)

## AI 지시

```text
[작업] 미션 촬영 → 사진 업로드 → (가짜) 판정 → 결과 화면 흐름을 만든다. (S4)

[먼저 읽기] AGENTS.md, 개발/연결명세.md 의 §2-5, §3 전체(특히 §3-1과 §3-4), §4, 기획서/환경이_기획서_복붙용.md 의 "주요 화면" ③④ 와 9장(안전·윤리·사용성)

[만들거나 고칠 파일] frontend/src/app/api.js, frontend/src/app/api.mock.js, frontend/src/app/image.js, frontend/src/app/screens/capture.js, result.js, candidates.js, error.js, 그리고 home.js·main.js의 연결 부분
1. api.js — verifyMission({ missionType, photoPath }), selectProduct({ missionId, productId }), getStatus({ simulateHours }) 세 함수. 맨 위에 명세 §3-4의 REAL 전환표(전부 false). false면 api.mock.js, true면 supabase.functions.invoke 를 쓴다.
2. api.mock.js — 명세 §3-1 응답 모양 그대로, 0.8초 늦게. 개발 모드에서만 보이는 선택 상자로 result 6종(awarded, no_points, retake, select_product, duplicate, limit_reached)과 오류(llm_failed)를 고를 수 있게 한다. 가짜 점수는 화면 표시용으로만 계산한다.
3. image.js — 사진을 긴 변 1024px JPEG(품질 약 0.85)로 줄인다. 휴대폰 사진이 눕지 않게 방향을 맞춘다.
4. capture.js — 미션별 촬영 가이드 문구
   - 빈 그릇: "다 먹은 그릇 전체가 보이게 찍어 주세요"
   - 친환경 제품: "제품 이름·용량·인증 마크가 보이게 찍어 주세요"
   - 환경 문구: "글자가 잘 보이게 찍어 주세요"
   - 공통: "사람 얼굴이 나오지 않게 해 주세요"
   <input type="file" accept="image/*" capture="environment">, 미리보기, 「인증하기」. 인증하기를 누르면 줄인 사진을 Storage mission-photos/{내 user id}/{uuid}.jpg 에 진짜로 올린 뒤 verifyMission을 부른다. 기다리는 동안 "판정 중…".
5. result.js — message, 미션별 근거(명세 §3-1 detail — 제품이면 인증 종류·인증번호·유효기간, 문구면 읽은 문구), 얻은 점수, "AI 판정은 틀릴 수 있어요" 안내, 「다시 찍기」「홈으로」. 인증 없는 제품은 "친환경이 아님"이 아니라 "공식 인증 정보 없음"으로 쓴다.
6. candidates.js — result가 select_product면 "이 제품이 맞나요?" 후보 목록과 「여기 없어요」. 고르면 selectProduct를 부르고 결과 화면으로.
7. error.js — 네트워크 오류·llm_failed일 때 쉬운 안내와 「다시 시도」.
8. home.js — 로그인 상태(session 있음)의 미션 버튼 → 촬영 화면 (S3의 "// 임시" 제거). 결과에서 홈으로 돌아오면: awarded일 때 celebrate(points), 응답의 score·remaining으로 setCleanliness·setRemaining. **게스트(session 없음) 쪽 미션 버튼과 GUEST_POINTS 로컬 점수 로직은 그대로 둔다 — 이 단계에서 고치지 않는다.**

[규칙] 판정 함수(Edge Function)는 아직 만들지 않는다 (S6). 점수를 DB에 쓰지 않는다. 게스트 모드는 건드리지 않는다. git 명령 실행 금지.

[끝나면] 파일 목록과 확인 순서를 알려주고 멈춘다.
```

## 확인

- [ ] 「빈 그릇 인증」 → 촬영 화면에 가이드 문구 → 사진 선택 → 미리보기 → 「인증하기」 → "판정 중…" → 결과 화면
- [ ] 선택 상자로 결과 6가지와 오류를 **하나씩** 골라 보고, 각각 화면이 알맞게 나온다
  - awarded → 홈에서 +점수가 떠오르고 점수·단계가 바뀜
  - select_product → 후보 화면 → 고르기 → 결과 / 「여기 없어요」 → "공식 인증 정보 없음"
  - llm_failed → 오류 안내와 「다시 시도」
- [ ] 대시보드 **Storage → mission-photos → 내 user id 폴더**에 사진이 있고, 크기가 500KB 이하다
- [ ] **남의 폴더에 못 올린다** — Console에 아래를 붙여넣고 Enter → `error`가 나온다
  ```
  await __supabase.storage.from('mission-photos').upload('someone-else/test.txt', new Blob(['x']))
  ```
- [ ] 휴대폰(`npm run dev -- --host`)에서 「인증하기」 전 촬영 버튼을 누르면 카메라가 바로 열린다
  - 참고: 이 방식은 휴대폰에서 카메라를 먼저 여는 방식이라 갤러리 선택을 완전히 막지는 못한다 (노트북 시연에서는 준비한 사진을 고를 수 있어야 해서 이대로 둔다)

## 막히면

- 업로드 때 `row-level security` 오류 → 경로의 첫 폴더가 내 user id인지 확인 (S2 Storage 정책)
- 사진이 옆으로 누움 → AI에게 "사진 방향(EXIF)을 반영해서 줄여줘"
- 결과 화면이 안 바뀜 → Console 오류를 AI에게 붙여넣기
