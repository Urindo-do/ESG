# S14. 완전성 점검·기능 동결

| 예상 | 난이도 | 앞 단계 |
|---|---|---|
| 60분 | ★★☆ | S13 (시간이 없으면 뺀 단계 다음) |

**끝나면**: 기획서에 약속한 것과 실제 앱을 한 줄씩 대조했고, 남은 임시 코드·비밀 값·규칙 숫자 문제를 확인했다. 이후에는 **시연에 보이는 버그만** 고친다.

## 사람이 먼저 할 일

- 받기 ([체크리스트 §2](../체크리스트.md#2-받기--매번-시작할-때))
- 배포 주소(휴대폰)와 노트북에서 앱을 열어 둔다

## 1. 기획서 대조 — 위에서 아래로 직접 해 본다

**8-1 핵심 기능**
- [ ] ① 빈 그릇 — 다 먹음 +10 · 남음 0점 · 애매하면 재촬영 · 하루 3회 · 같은 사진 차단
- [ ] ② 친환경 제품 — 인증 카드 +10 · 후보 선택 · 인증 없으면 0점과 "공식 인증 정보 없음" · 하루 2개 · 같은 사진 차단
- [ ] ③ 환경 문구 — +1 · 읽은 문구 표시 · 하루 10개 · 같은 문구를 다른 사진으로 다시 인증 가능

**8-2 화면**
- [ ] ① 로그인·회원가입 (이메일·비밀번호·닉네임)
- [ ] ② 홈 — 마을과 캐릭터, 점수 게이지와 단계 이름, 남은 횟수, 미션 버튼 3개 (3D면 시점 회전·확대·카메라 초기화도)
- [ ] ③ 촬영 — 미션별 가이드 → 미리보기 → 인증하기
- [ ] ④ 판정 결과 — 판정 문구, 근거, 점수, "AI 판정은 틀릴 수 있어요", 「다시 찍기」
- [ ] ⑤ 상태 변화 연출 — 오르면 반짝임, 내리면 먼지
- [ ] ⑥ 인증 기록 (S13을 뺐다면 발표에서 "향후"로 설명)

**8-3 · 7장**
- [ ] AI — 미션별 프롬프트 3종, 정해진 JSON만 받음, 확신도가 낮으면 재촬영
- [ ] 데이터 — 유효기간 지난 인증 제외, 인증 종류 정리, 검색용 이름
- [ ] 점수 규칙 — 하루 제한, 중복 사진 차단, 48시간 후 감소 (`deno test supabase/functions/_shared/` 다시 실행 → 전부 통과)

**9장 안전·윤리·사용성**
- [ ] 이메일·닉네임 말고는 개인정보를 받지 않는다
- [ ] AI 키는 서버 비밀값에만 있다 (아래 AI 점검 2번)
- [ ] 사진은 본인만 볼 수 있다 (S3·S4에서 확인)
- [ ] 촬영 가이드에 "사람 얼굴이 나오지 않게"가 있다
- [ ] 인증 없는 제품을 "친환경이 아님"이라고 쓰지 않는다
- [ ] 국물·소스 음식이 불리하지 않은지 확인했다 (S6 메모)
- [ ] 쉬운 말, 오류가 나면 안내와 「다시 시도」
- [ ] 데이터 출처와 사용 가능 여부를 확인했다 (환경성적표지 확인됨 / 환경표지는 S8 결과)

## 2. AI 점검 (읽기만)

```text
[작업] 저장소를 점검하고 결과만 보고한다. 파일은 고치지 않는다. (S14)

[먼저 읽기] AGENTS.md, 개발/연결명세.md

[점검]
1. "// 임시:" 주석이 남은 곳 — 파일, 줄, 무엇이 임시인지
2. 비밀 값 — sb_secret_, service_role, API 키처럼 보이는 문자열이 저장소 파일(코드·문서)에 있는지
3. 규칙 숫자 — 점수·한도·감소 숫자가 supabase/functions/_shared/rules.ts 밖에, 청결 경계값(MOOD_THRESHOLDS)이 frontend/src/config.js 밖에 쓰인 곳
4. 명세와 다른 곳 — 연결명세의 result 값·필드 이름·함수 이름과 코드가 다른 곳
5. frontend/src/app/api.js의 REAL 전환표가 전부 true인지

[끝나면] 항목별로 "문제 없음" 또는 파일·줄·내용을 표로 보여주고 멈춘다.
```

## 3. 고치기

- 위 1·2에서 나온 문제를 **시연에 영향이 큰 것부터** 목록으로 적는다
- **한 번에 하나씩**: AI에게 그 항목만 고치게 → 직접 확인 → 올리기 (`fix:` 커밋)
- 비밀 값이 저장소에 올라갔다면 **그 키를 바로 폐기하고 새로 발급**한다 (지워도 GitHub 기록에 남는다) — 멘토님께도 알린다
