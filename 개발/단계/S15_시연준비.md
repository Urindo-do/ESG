# S15. 시연 준비·리허설

| 예상 | 난이도 | 앞 단계 |
|---|---|---|
| 60분 | ★☆☆ | S14 |

**끝나면**: 시연 순서표와 시연 계정 초기화 방법이 준비되고, 리허설을 2번 통과했으며, 만일을 위한 녹화 영상과 발표 자료가 있다.

## 사람이 먼저 할 일

1. 받기 ([체크리스트 §2](../체크리스트.md#2-받기--매번-시작할-때))
2. **시연 계정** 정하기 — 시연 전용 Google 계정으로 한 번 로그인해 둔다 (Google이 안 되는 상황 대비로 테스트용 이메일 계정도 하나)
   - 이메일 가입은 실제로 있는 도메인으로 (`example.com`·`test.com`은 거절될 수 있음)
3. Supabase 비밀값 `DEMO_MODE`가 `true`인지 확인

## AI 지시

```text
[작업] 시연 순서표와 시연 계정 초기화 SQL을 만든다. (S15)

[먼저 읽기] AGENTS.md, 기획서/환경이_기획서_복붙용.md 의 "시연 시나리오", 개발/연결명세.md 의 §1-1, 시연/README.md, 시연/사진/ 의 파일 목록

[만들 파일] 시연/시나리오.md, 시연/초기화.sql
1. 시나리오.md — 시나리오 5개를 순서대로. 각각 쓸 사진 파일 이름, 누를 버튼, 기대 결과, 점수 변화, "안 될 때 말할 문장" 한 줄.
   점수 흐름: 시작 50 → ① 빈 그릇 60 → ② 인증 제품 70 → ③ 인증 없는 과자 70 → ④ 캠페인 배너 71 → ⑤ 주소 끝 ?demo=1, 「시간 경과」 120시간 → 31 '꼬질꼬질'
2. 초기화.sql — 맨 위 한 곳에 시연 계정 이메일을 적으면 (저장소에는 '여기에_시연_계정_이메일' 같은 자리 표시로 두고, 실제 주소는 실행할 때만 넣는다), 그 계정의 missions를 지우고 profiles를 score 50, last_mission_at 지금으로 되돌린다. 다른 계정에는 영향이 없어야 한다. 실행 전에 대상을 보여 주는 select를 먼저 둔다.

[규칙] 다른 파일은 고치지 않는다. git 명령 실행 금지.

[끝나면] 파일 목록과 초기화 SQL 사용법을 알려주고 멈춘다.
```

## 사람이 할 일

1. **초기화 연습** — SQL Editor에서 `시연/초기화.sql`의 select만 먼저 실행해 대상이 시연 계정 하나인지 확인 → 전체 실행 → 앱에서 50 · '보통' 확인
2. **리허설 2회** — `시연/시나리오.md` 순서대로, 실제 시연과 같은 화면(노트북 또는 휴대폰 미러링)으로. 걸린 시간을 잰다. 리허설 사이에 초기화
3. **녹화 백업** — 리허설 한 번을 화면 녹화해 둔다 (와이파이·AI 지연 대비)
4. **발표 자료** — 문제 → 해결 → AI 구조([아키텍처 그림](../../기획서/환경이_AI_아키텍처.png)) → 시연 → 한계와 향후 계획(바코드·QR 연동 등)
   - 가이드가 LangChain·LangGraph 활용을 권하므로, 우리 AI가 하는 일(사진 판정 → 인증 DB 검색 → 규칙 채점)을 **판단·검색·자동화** 관점으로 분명히 설명할 준비를 한다
5. **기획서 빈칸** — 팀명·팀장·역할·날짜·데이터 출처 체크. hwp를 고쳐야 하면 수정 요청 (복붙용 md도 함께 맞춘다)
6. **시연 직전** — 초기화 → 「Google로 시작하기」로 로그인 → 50 · '보통' 확인 → 사진을 순서대로 준비 (휴대폰이면 크롬·사파리로 연다)
