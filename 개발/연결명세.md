## 1. 점수 규칙 상수

**원본 위치** — 서버 규칙: `supabase/functions/_shared/rules.ts` / 청결 단계 경계: `frontend/src/config.js`의 `MOOD_THRESHOLDS`.
이 두 파일 밖에서 아래 숫자를 직접 쓰지 않는다.

| 이름 | 값 (초안) | 비고 |
|---|---|---|
| 점수 범위 | 0 ~ 100 | 더할 때 상한·하한으로 자른다 |
| 초기 점수 | 65 | `결정 필요` — '기본'에서 시작하면 첫 +10(75)에 'happy'로 바뀌어 시연에서 잘 보임 (9/17: 청결 3단계로 변경됨 — 아래) |
| 빈 그릇 (`meal`) | +10, 하루 3회 | |
| 친환경 제품 (`product`) | +10 (인증 없음 0), 하루 2개 | |
| 환경 문구 (`phrase`) | +1, 하루 10개 | 기준 점수의 0.1배 |
| 하루 한도 세는 기준 | **점수를 받은 인증만** 센다 | `결정 필요` — 0점·재촬영은 한도를 쓰지 않음 |
| 하루 전체 판정 호출 상한 | 30회 (결과 상관없이) | `결정 필요` — AI 호출 비용 보호용 |
| 확신도 기준 | 0.7 | `결정 필요` — 미만이면 점수 없이 재촬영 안내. 시연하며 조절 |
| 제품 자동 확정 기준 | 1순위 유사도 0.6 이상 **이고** 2순위보다 0.1 이상 높을 때 | `결정 필요` — 아니면 후보 선택 화면 (`아이시스`처럼 이름이 비슷한 변형이 많을 때 잘못 확정하지 않게) |
| 감소 시작 | 기준 시각 후 48시간 | 기준 시각 = `profiles.last_mission_at` |
| 감소량 | 48시간 시점에 -10, 이후 24시간마다 -10 | `결정 필요` — 기획서 "48시간이 지나면 24시간마다 -10"을 *48시간이 되는 순간 첫 감소*로 해석. 아래 예시 표로 테스트 |
| 하루의 기준 | **한국시간(Asia/Seoul) 00:00** | 서버는 UTC로 돌기 때문에 반드시 변환 |
| 중복 사진 | 같은 사용자가 같은 파일(해시 동일)을 다시 내면 거절, 3종 공통 | `결정 필요` — ③의 "중복 허용"은 *같은 문구를 다른 사진으로* 다시 인증해도 된다는 뜻으로 해석 |
| 청결 3단계 (9/17 변경) | happy 70~100 · 기본 30~69 · sad 0~29 | 마을 모듈만 사용. 서버는 단계를 몰라도 됨. 원래 5단계 계획이었으나 팀원이 만든 3D 마을이 3단계 + 점수에 따라 연속으로 진해지는 먼지·시듦 효과로 구현되어 이 버전을 채택함 (기획서 5단계 설명보다 이 표가 우선) |

### 1-1. 감소 계산 (조용히 틀리기 쉬운 곳 — 테스트로 고정)

```
경과시간 = 지금 - last_mission_at
경과시간 < 48시간          → 감소 없음
경과시간 ≥ 48시간          → 감소 횟수 = floor((경과시간 - 48) / 24) + 1
현재 점수 = max(0, 저장된 점수 - 10 × 감소 횟수)
```

| 경과 시간 | 47h | 48h | 71h | 72h | 96h | 30일 |
|---|---|---|---|---|---|---|
| 저장 점수 60일 때 현재 점수 | 60 | 50 | 50 | 40 | 30 | 0 |

- 감소는 **읽을 때 계산**한다 (DB에 매시간 쓰지 않음, 예약 작업 불필요).
- 점수를 **받은** 인증이 있을 때만: `새 점수 = min(100, 현재 점수 + 얻은 점수)`, `score = 새 점수`, `last_mission_at = 지금`으로 저장한다.
- 0점·재촬영은 `last_mission_at`을 바꾸지 않는다 (아무 사진이나 내서 감소를 피하는 것 방지).
- 가입할 때 `last_mission_at = 가입 시각`으로 시작한다.

## 2. DB (Supabase Postgres) — S2에서 만듦

대시보드 SQL Editor에서 실행한 SQL은 **반드시 같은 내용으로** `supabase/migrations/`에 파일로 남긴다 (예: `20260917000001_init.sql`).

### 2-1. `profiles` — 사용자 1명당 1행

| 컬럼 | 타입 | 규칙 |
|---|---|---|
| `id` | uuid, PK | `auth.users.id`와 같음 |
| `nickname` | text, 필수 | 가입할 때 넘긴 값, 없으면 `새싹` |
| `score` | int, 필수, 기본 50 | 0~100 체크. **마지막 갱신 시점 기준** 점수 (감소 전) |
| `last_mission_at` | timestamptz, 필수 | 가입 시각으로 시작, 점수를 받은 인증 때만 갱신 |
| `created_at` | timestamptz | 기본 now() |

- 가입하면 트리거가 자동으로 1행 만든다 (닉네임은 가입 때 넘긴 사용자 메타데이터 `nickname`).

### 2-2. `missions` — 인증 시도 1건당 1행

| 컬럼 | 타입 | 규칙 |
|---|---|---|
| `id` | uuid, PK | 기본 `gen_random_uuid()` |
| `user_id` | uuid, 필수 | → `profiles.id` |
| `type` | text, 필수 | `meal` \| `product` \| `phrase` |
| `photo_path` | text, 필수 | Storage 경로 |
| `image_hash` | text, 필수 | 사진 파일의 SHA-256 (서버가 계산) |
| `status` | text, 필수 | `awarded` \| `no_points` \| `retake` \| `pending_selection` |
| `ai_result` | jsonb | 형식 검사를 통과한 LLM 응답 + (제품이면) 후보 목록 |
| `product_id` | bigint | → `eco_products.id`, 제품 확정 시만 |
| `points` | int, 필수, 기본 0 | 실제로 준 점수 |
| `score_after` | int | 이 인증을 반영한 뒤의 점수 (기록 화면의 "점수 변화" 표시용, 기획서 7-2 ⑦) |
| `created_at` | timestamptz | 기본 now() |

- `unique (user_id, image_hash)` — 중복 사진의 마지막 방어선.
- `duplicate`·`limit_reached`는 AI를 부르지 않으므로 행을 만들지 않는다.

### 2-3. `eco_products` — 공식 인증 제품 (S8에서 적재)

| 컬럼 | 타입 | 규칙 |
|---|---|---|
| `id` | bigint, PK | 자동 증가 |
| `cert_type` | text, 필수 | `환경표지` \| `환경성적` \| `저탄소제품` |
| `cert_no` | text, 필수 | 인증번호 (예: `2024-240`) |
| `company` | text | 기업명 |
| `product_name` | text, 필수 | 원본 제품명 (예: `아이시스ECO[500mL,PET]`) |
| `search_name` | text, 필수 | 검색용 이름 (아래 규칙) |
| `valid_from` / `valid_to` | date | 인증 시작·종료일 |
| `source` | text | 원본 파일 이름 |

- 검색할 때도 `valid_to >= 오늘(한국시간)`만 본다 (적재 뒤에도 만료되는 제품이 생김).

**검색용 이름 규칙** — S8의 파이썬(`data/scripts/`)과 S9의 함수(`_shared/normalize.ts`)가 **똑같이** 만든다. 아래 예시가 곧 테스트다.

1. 영문은 소문자로
2. `[` `]` `(` `)` `,` 는 공백으로
3. 한글과 영문·숫자가 붙어 있으면 사이에 공백
4. 용량은 ml로 통일 (`2.0l` → `2000ml`, `1.5l` → `1500ml`)
5. 공백 여러 개는 하나로, 앞뒤 공백 제거

| 입력 | 결과 |
|---|---|
| `아이시스ECO[500mL,PET]` | `아이시스 eco 500ml pet` |
| `아이시스8.0ECO[1500mL,PET]` | `아이시스 8.0eco 1500ml pet` |
| `농협 전용 아이시스[2.0L,PET]` | `농협 전용 아이시스 2000ml pet` |
| `아이시스 ECO 500mL` (AI가 읽은 값) | `아이시스 eco 500ml` |

### 2-4. 검색 함수 `search_eco_products(q text, max_results int default 5)`

- 반환: `id, cert_type, cert_no, company, product_name, valid_from, valid_to, similarity` — 유사도 높은 순.
- 기본안: `pg_trgm` 확장 + `search_name`에 GIN 인덱스.
- ⚠️ **한글에서 동작하는지 S2에서 먼저 확인** (`pg_trgm`은 DB 문자 설정에 따라 한글을 못 쪼갤 수 있음):
  ```sql
  create extension if not exists pg_trgm with schema extensions;
  show lc_ctype;
  select extensions.show_trgm('아이시스');
  select extensions.similarity('아이시스 eco 500ml pet', '아이시스 eco 500ml');
  ```
  - `show_trgm` 결과가 `{}`(빈 배열)이면 한글 불가 → **대체안**: `search_name ilike '%단어%'`로 후보를 넓게 가져온 뒤, 함수(S9)에서 글자 겹침 비율로 정렬한다. 유효 제품이 약 2,800개라 충분히 빠르다.
  - Supabase는 확장을 `extensions` 스키마에 두므로, 함수 안에서는 `extensions.similarity(...)`처럼 스키마를 붙여 부른다.
- 사실 확인: `아이시스`로 찾으면 **7개 변형**(ECO 500mL·ECO 2000mL·8.0 500mL 등)이 나온다. 시연 제품(`2024-240`, 아이시스ECO 500mL)이 1순위가 되려면 **용량·ECO 표기까지** 검색어에 들어가야 한다.

### 2-5. 접근 권한 (RLS) — 점수 조작 방지

| 표 / 버킷 | 로그인 사용자가 할 수 있는 것 | 쓰기는 |
|---|---|---|
| `profiles` | 자기 행 **읽기만** | 가입 트리거 · 함수(관리자 키) |
| `missions` | 자기 행 **읽기만** | 함수(관리자 키) |
| `eco_products` | 전체 읽기 | 적재(S8, 대시보드) |
| Storage `mission-photos` | 자기 폴더 `{user_id}/`에 올리기·읽기 | — |

- 브라우저에서 `profiles.score`를 직접 바꿀 수 있으면 게임이 무너진다. S3에서 **바뀌지 않는지** 꼭 확인.
- RLS는 막힌 수정을 오류 없이 "0행 수정"으로 끝낸다. 그래서 확인은 "오류가 났나"가 아니라 **"값이 그대로인가"** 로 한다.

## 3. 판정 API (Supabase Edge Functions)

- 호출: `supabase.functions.invoke('<함수 이름>', { body })` — 로그인한 상태면 사용자 토큰이 자동으로 붙는다.
- 함수는 기본 JWT 검사(verify_jwt)를 켠 채로 두고, 토큰에서 사용자 ID를 얻는다 (코드 모양은 공식 문서 [Securing Edge Functions](https://supabase.com/docs/guides/functions/auth) 기준).
- 관리자 키는 함수에 **자동 주입된 값**만 읽는다 (`SUPABASE_SERVICE_ROLE_KEY`, 또는 새 방식 `SUPABASE_SECRET_KEYS`의 `default`). LLM 키는 비밀값 `LLM_API_KEY`만 읽는다.
- **업무 결과(중복·한도·재촬영 등)는 HTTP 200 + `result`로** 준다. 4xx/5xx는 진짜 오류에만 쓴다 (화면에서 다루기 쉬움).

### 3-1. `verify-mission`

**사진 순서**: 화면이 먼저 Storage `mission-photos/{user_id}/{uuid}.jpg`에 올린다 (긴 변 1024px JPEG) → 경로를 넘겨 호출.

요청 (인증):
```json
{ "missionType": "product", "photoPath": "5f1c…/a8e2….jpg" }
```

요청 (제품 후보 선택 확정):
```json
{ "action": "select_product", "missionId": "c1d2…", "productId": 749 }
```
- `productId: null` = "여기 없어요" → 0점, "공식 인증 정보 없음".
- 함수는 그 미션이 본인 것인지, `pending_selection` 상태인지, `productId`가 저장된 후보 안에 있는지 확인한다.

응답 (공통 모양):
```json
{
  "missionId": "c1d2…",
  "missionType": "product",
  "result": "awarded",
  "points": 10,
  "score": 60,
  "remaining": { "meal": 3, "product": 1, "phrase": 10 },
  "message": "공식 인증 제품이에요! +10점",
  "detail": {
    "read": { "product_name": "아이시스 ECO", "brand": "롯데칠성음료", "volume": "500mL", "cert_marks": ["저탄소"], "confidence": 0.91 },
    "matched": { "id": 749, "cert_type": "저탄소제품", "cert_no": "2024-240", "company": "롯데칠성음료 (주)", "product_name": "아이시스ECO[500mL,PET]", "valid_to": "2027-04-24" },
    "candidates": []
  }
}
```

- `score`: 감소까지 반영한 **지금** 점수 → 화면은 이 값을 그대로 `village.setCleanliness(score)`에 넘긴다.
- `remaining` → 그대로 `village.setRemaining(remaining)`.
- `message`: 화면에 그대로 보여줄 쉬운 문장 (전문용어 없이).

`result` 6종:

| result | 뜻 | 점수 | 화면 |
|---|---|---|---|
| `awarded` | 인정 | +점수 | 결과 카드 → 홈에서 `celebrate(points)` |
| `no_points` | 판정은 됐지만 점수 없음 (음식 남음 / 인증 정보 없음 / 환경과 무관한 문구) | 0 | 결과 카드 (인증 없음은 "친환경이 아님"이 아니라 **"공식 인증 정보 없음"**) |
| `retake` | 확신도 낮음 · AI 응답 형식 오류 · 제품명 못 읽음 | 0 | "다시 찍어 주세요" + 촬영 가이드 |
| `select_product` | 제품 후보 중 선택 필요 | 아직 없음 | 후보 선택 화면 (`detail.candidates`) |
| `duplicate` | 같은 사진 재사용 | 0 | 안내만 (AI 호출 안 함) |
| `limit_reached` | 오늘 이 미션 한도 / 전체 호출 상한 | 0 | 안내만 (AI 호출 안 함) |

`detail` 미션별 모양:

| missionType | detail |
|---|---|
| `meal` | `{ "verdict": "empty"\|"leftover"\|"unknown", "confidence": 0.93, "reason": "그릇에 남은 음식이 보이지 않아요" }` |
| `product` | `{ "read": {…§5-2}, "matched": {…} 또는 null, "candidates": [ {id, cert_type, cert_no, company, product_name, valid_to, similarity} ] }` |
| `phrase` | `{ "text": "종이 영수증 대신 전자영수증 발급받기", "is_environmental": true, "confidence": 0.95 }` |

진짜 오류 (4xx/5xx):
```json
{ "error": "llm_failed", "message": "판정 중 문제가 생겼어요. 잠시 후 다시 시도해 주세요." }
```
`error` 값: `bad_request`(400) · `unauthorized`(401) · `not_found`(404) · `llm_failed`(502) · `internal`(500)

**처리 순서**: 로그인 확인 → 입력 검사 → 사진 내려받기 → 해시 → 중복 검사 → 한도 검사 → LLM 판정(§5) → 형식 검사 → (제품이면 §2-4 검색) → 점수 계산(§1) → `missions` 기록·`profiles` 갱신 → 응답

### 3-2. `get-status` — 홈 화면을 열 때

요청: `{}` · 시연용 `{ "simulateHours": 72 }` (비밀값 `DEMO_MODE=true`일 때만 받음, 저장은 안 함)

응답:
```json
{ "nickname": "지우", "score": 40, "lastMissionAt": "2026-09-17T11:00:00Z", "remaining": { "meal": 3, "product": 2, "phrase": 10 } }
```

### 3-3. 인증 기록 (함수 없이 화면이 직접 조회)

- `missions`를 `created_at` 내림차순으로 읽는다 (RLS로 자기 것만 보임). 점수 변화는 `points`와 `score_after`로 보여 준다.
- 사진은 `storage.from('mission-photos').createSignedUrl(path, 60)`으로 잠깐 볼 수 있는 주소를 받는다.

### 3-4. 가짜 API와 전환표

- `frontend/src/app/api.mock.js`가 위 예시 응답을 **0.8초 늦게** 돌려주고, `result` 6종과 오류를 골라서 낼 수 있게 한다 (개발 모드에서만 보이는 선택 상자).
- `frontend/src/app/api.js` 맨 위에 전환표를 둔다. 진짜로 바꾸는 단계에서 **자기 줄만** `true`로 바꾼다.

```js
// 진짜 서버로 보낼지 여부 — 단계가 끝날 때마다 한 줄씩 true
export const REAL = {
  meal: false,    // S6
  product: false, // S9
```

## 4. 마을 API — S1(2D 대역)·S12(3D)에서 만듦

원문: [3D 화면 프롬프트](../기획서/환경이_3D화면_프롬프트.md) "연결 약속(API)".

```js
import { createVillage } from './village/village.js';

const village = createVillage(document.querySelector('#village'));
village.setCleanliness(score);                    // 0~100, 단계 전환 연출 포함

village.celebrate(points);                        // +points 표시, 정화 효과
```

- 마을 모듈은 로그인·카메라·Supabase·API 키를 **직접 다루지 않는다**.
- **(9/17 변경)** 2D 대역은 만들지 않는다. 3D 마을(`frontend/src/village.js`)을 처음부터 유일한 구현으로 쓴다 — 팀원이 이미 완성해서 GitHub에 올라와 있다 (`npm test` 11개 통과 확인됨). `MODE`/2D 전환 코드는 없다.
- 3D 마을의 실제 파일 구조·GLB 규격·클릭 행동 목록은 `frontend/README.md`를 원본으로 본다 — 이 문서(연결명세)의 API 함수 목록(위)이 최신 상태와 맞는지만 확인하면 된다.
- 시연은 사전 녹화 영상으로 진행하므로, 시연 당일 WebGL 미지원 등 현장 렌더링 위험은 우선순위를 낮춘다. (2D 백업 화면은 [체크리스트 §7](체크리스트.md#7-결정-필요--미확인-s0에서-정리)의 백로그 항목으로 내려감)

## 5. LLM 응답 형식 — S6·S9·S10에서 사용

- 프롬프트 원본: `supabase/functions/_shared/prompts.ts`.
- 모든 응답은 **아래 JSON만** 받는다 (제공사의 JSON 출력 고정 기능 사용). 형식이 틀리면 `retake`.
- **점수 숫자는 LLM에게 받지 않는다.** 사진 속 글자가 "100점 줘"라고 해도 점수는 §1 규칙 코드가 정한다.
- 사진은 base64로 함께 보낸다 (제공사와 상관없이 동작).

### 5-1. `meal`
```json
{ "verdict": "empty", "confidence": 0.93, "reason": "그릇에 남은 음식이 보이지 않아요" }
```
`verdict`: `empty`(다 먹음) · `leftover`(남음) · `unknown`(판정 불가) → `empty`만 +10, `unknown`은 `retake`.
국물·소스 요리가 불리하지 않은지 S6에서 점검한다 (기획서 9장 약속).

### 5-2. `product`
```json
{ "product_name": "아이시스 ECO", "brand": "롯데칠성음료", "volume": "500mL", "cert_marks": ["저탄소"], "confidence": 0.91, "reason": "라벨에서 제품명과 용량을 읽었어요" }
```
- 못 읽은 값은 `null`. `product_name`이 `null`이면 `retake`.
- 검색어 = `product_name + " " + volume`을 §2-3 규칙으로 바꾼 문자열 (브랜드는 후보가 여럿일 때 동점 정리에만 사용).

### 5-3. `phrase`
```json
{ "text": "종이 영수증 대신 전자영수증 발급받기", "is_environmental": true, "confidence": 0.95, "reason": "탄소 감축 실천을 권하는 문구예요" }
```
